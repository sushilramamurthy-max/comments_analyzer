Author & editor insights

What authors and editors are telling you — turned into who should fix it.

Author and editor comments happen at the very start of the workflow, before anything reaches production. Each one either flags something the product can't yet do — a product comment — or is a normal editorial note about the manuscript itself — a content comment. This page exists to close the loop: comment in, insight out, owner assigned, count goes down.

Mastercopier insights

Mastercopiers should only ever leave a layout comment.

Every mastercopier comment is production staff typing an instruction because the product won't let them just do it themselves. Their comments already come tagged with a category — XML, Graphics, Layout, or Text. Layout is the one category that will always need a human judgment call. XML, Graphics, and Text shouldn't need a comment at all — they should be something a mastercopier finishes with a click, in the tool, without ever leaving a note for someone else to act on.

How this works. Comments are grouped by normalized text (numbers collapsed) plus role, so the same instruction recurring across articles is classified once and cached. Classification runs via Claude, capped at 300 new patterns per upload for speed — anything beyond that is counted in totals as "unclassified / long tail" and gets picked up automatically on a future upload if it keeps recurring. Data is stored on this app's server, not shared externally.
